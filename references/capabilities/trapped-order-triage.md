# 被套单排障（逻辑被否认即离场）

## R — 原文（Reading）

> 就不能那什么就不能有被套单 / 能懂我什么意思吗 / 都不能有被套单 / 在我的概念里不要有被套的订单

— 交易员江河，ep-2026.8.14 L01276–L01302

---

> 我从来不做这种什么解套行为 / 因为我从来不被套 / 我从来不被套 / 所以说我不做解套行为

— 交易员江河，ep-2026.8.14 L01344–L01349

---

## I — 方法论骨架（Interpretation）

"被套"不是一个状态，是一个错误的延续。作者的主张是：**概念里不要有被套的订单**。

推理链只有三步：进场做多，是因为认为它会涨 → 它没涨，就说明这条理由被否认 → 逻辑被否认就不该一直拿着。所以处置被套单的动作不是"想办法解套"，而是"确认逻辑是否被否认，被否认就走"。

"解套行为"（补仓、扛单、等回本）之所以被禁止，是因为它默认"价格一定会回来"。而作者把带止损当作前提：只要进场就带止损、止损挂在逻辑否认点，价格走到那里单子自动了结，**根本不会进入被套状态**，也就不需要解套行为。补仓解套之所以危险，是它把一次可承受的止损成本，换成了越补越深、越扛越久的不可逆敞口。

需要与相邻能力分清：`order-exit-discipline` 管的是"出口合法性"——规定哪些离场方式被允许（打止损或赚钱离场，不割肉、不推保本）。本能力管的是"**已经偏离预期时怎么处置**"——当单子确实已经浮亏、已经偏离进场逻辑，判的是"逻辑是否被否认、该不该走"。前者是规则约束，后者是排障流程；有了前者的规则，被套这种状态本不该出现，一旦出现，就用本能力把它结束掉。

新材料补了一层"为什么必须带止损"的说明：止损从单笔看是敌人（它让你亏钱），从整体看是朋友。作者对不带止损表示无法理解——"就是我一直都理解不太了就是做订单不带止损的那得套多狠呐"（ep-2026.7.25 L1772、L1080）。扛单不割肉的人的逻辑是"我不卖对吧我不割肉我就不亏"，但侥幸扛单从亏损扛到盈利会强化侥幸心理，下一次更信侥幸，直到一次加速行情被拉爆。开对冲单同样违背目的：不带止损做交易，等于把唯一能控制的成本也放弃掉（ep-2026.8.22 L61、L65）。

## A1 — 应用示例（Application Example）

### 示例 1: 合成演练 —— 跌破逻辑否认点的多单
- **类型与来源**: 原书未提供该场景的成交案例；以下为合成演练（口径来源 ep-2026.8.14 L01276–L01302）
- **问题/输入**: 用户一笔多单已浮亏，价格跌破进场时写下的逻辑否认点，用户问"要不要补一点仓摊低成本""这个价位的多还有没有救"。
- **方法论的使用**:
 1. 调出进场逻辑：当时做多是因为"该位置回踩不破、继续向上"
 2. 对照当下：价格已经跌破那个位置 → 逻辑否认点被触及 → 逻辑被否认
 3. 判停：逻辑被否认 → 离场，不接受"补仓摊低"这个选项
 4. 若该单根本没有止损位 → 先补挂止损并立即了结，再回到 `position-sizing-by-stop` 复盘为什么没有止损
- **结论**: 离场，不做解套行为。
- **结果**: 演练，未说明。

### 示例 2: 合成演练 —— "只是插针打损、逻辑没被否认"
- **类型与来源**: 原书未提供该场景的成交案例；以下为合成演练（口径来源 ep-2026.8.14 L01276–L01302、原文 ）
- **问题/输入**: 用户一笔多单被一根长下影插针打掉止损，价格随即收回，逻辑否认点并未被收盘确认跌破，用户问"能不能再做一次"。
- **方法论的使用**:
 1. 区分"止损被打掉"与"逻辑被否认"：前者是概率成本，后者才是排障判据
 2. 检查逻辑否认点：仅被影线触碰、未收盘跌破 → 逻辑未被否认
 3. 结论：可以在原逻辑上再做，但这属于"同一逻辑的第二次机会"，需并入 `consecutive-loss-stop` 的计数
- **结论**: 逻辑未被否认，可再做；但计入同一逻辑的连损计数。
- **结果**: 演练，未说明。

## A2 — 触发场景（Future Trigger）★

### 用户会在什么情境下需要这个能力？

1. 用户说"我这单被套了""扛一扛能不能回来"。
2. 用户问"某某价位的多还有没有救""要不要补仓摊低成本"。
3. 用户浮亏已扩大，问"要不要再等等、等它回到成本价"。
4. 用户说"我不想止损，怕损了它又回来"。
5. 用户手里有一笔没有止损、已经深度浮亏的单，来问怎么处理。

### 语言信号（用户的话里出现这些就应激活）

- "被套了 / 扛单 / 扛一扛 / 等回本"
- "补仓摊低成本 / 补补仓就回来了 / average down"
- "有没有救 / 还有没有希望 / trapped order"
- "我不想止损 / 怕损了再回来 / 舍不得成本"
- "解套 / 等它回到成本价"

### 与相邻能力的区分

- 与 `order-exit-discipline` 的区别（**最容易混**）: order-exit-discipline 管"**出口合法性**"——规定一笔单只允许打止损或赚钱离场，割肉与推保本都不合法；本能力管"**已经偏离预期时怎么处置**"——当单子已经浮亏、已经偏离进场逻辑，判"逻辑是否被否认、该不该走"。一句话：前者回答"哪些出口允许"，后者回答"现在这个局面怎么收"。若两者冲突（例如用户想"割掉一点"），以 order-exit-discipline 的出口规则为准。
- 与 `stop-loss-mechanics` 的区别: stop-loss-mechanics 只处理浮盈阶段的止损位移，并明确"亏损单不再挪止损"；本能力处理的是"亏损单要不要直接走"。被套单不适用移动止损。
- 与 `consecutive-loss-stop` 的区别: 本能力处理**单笔**被套单的去留；consecutive-loss-stop 处理**同一逻辑连续被否认**时的停手。示例 2 的"再做一次"必须计入后者的计数。
- 与 `setup-gate` 的区别: 若一笔单从一开始就说不清逻辑，那它不该存在；本能力只处理"进场时说得清、现在被否认"的单。

## E — 可执行步骤（Execution）

**必需输入**: 进场价与方向；进场时写下的逻辑（一句话）与逻辑否认点价位；当前价；当前浮亏；用户当下的诉求（补仓/扛单/离场）。若拿不到"进场逻辑"或"逻辑否认点"，先追问；两者都拿不到，则按"无逻辑单"处理（见步骤 2 判停）。

**交付物与完成标准**: 输出一份**处置判定** —— `逻辑是否被否认`（是/否/无法判定）、`处置动作`（离场 / 保留但计入连损 / 立即补挂止损后了结）、`依据`、`禁止的动作`（补仓、扛单、无限试单）。完成标准：判定为"是"时必须能指到具体价位与触发方式（收盘确认还是影线）；判定为"无法判定"时必须写明"缺哪个输入"，不得默认按"没被否认"处理。

**实现约定**: 原文只说"逻辑被否认就走""不能有被套单"，未给出①"被否认"的量化判据（收盘确认 vs 影线触及）；②"被套"的浮亏门槛。本卡把以下取值标为**实现约定**：① "逻辑被否认"＝逻辑否认点被**收盘价**穿越（影线触及不算），或进场结构被反向打破；② "无逻辑单"＝进场时说不出逻辑或说不出逻辑否认点，这类单视为已经"被否认"，直接了结；③ 被套判定不设浮亏门槛，只要逻辑被否认即成立。

1. **取出进场逻辑与逻辑否认点**
 - 完成标准: 能写出"我做这笔单是因为 X"与一个明确价位。
 - 判停条件: 两者都拿不到 → 判为"无逻辑单"，**直接了结**，跳到步骤 5。
2. **判断逻辑是否被否认**
 - 完成标准: 给出是/否，并写明是收盘穿越还是结构打破。
3. **检查是否存在"解套"诉求**
 - 完成标准: 若用户提出补仓/扛单/等回本，逐条拒绝并说明理由（补仓把可承受成本换成不可逆敞口）。
4. **给出处置动作**
 - 完成标准: 逻辑被否认 → 离场；逻辑未被否认（如插针打损）→ 可保留或再做，但计入 `consecutive-loss-stop` 的同一逻辑计数。
5. **确认止损在位**
 - 完成标准: 无论结论如何，这笔单（或下一笔）必须有挂在逻辑否认点的止损；没有就先补挂。
6. **记录**
 - 完成标准: 记下这笔单的"被否认判定 + 依据 + 动作"，供复盘口径统计（区分概率损与系统之外的错）。

## B — 边界（Boundary）★

### 不要在以下情况使用

- **浮盈中的正常回吐**。示例：浮盈从 1 万 5 回吐到 5000 仍持有，那不是被套，是动态离场的正常代价；此时用本能力会把"回撤"误判成"被套"。
- **止损被影线打掉但逻辑未被否认**。这是概率成本，不是被套；不要因为"被打损了"就认定逻辑错了。
- **用它来给"先割掉一部分"找理由**。出口合法性归 `order-exit-discipline`。

### 作者警告的失败模式

- **被套扛单 / 补仓解套**（ep-2026.8.14 L01344–L01349）。陷阱：不带止损、被套后补仓扛单，指望价格回来解套；也指卖飞/错过之后转为扛单或无限试单、一路抄底。机制：做多的前提是认为它会涨，它没涨就说明进场逻辑已被否认；不认错、舍不得止损成本、怕损了再回来，就会越补越多、越扛越深，最终承担爆仓风险。预警信号："我补补仓一下子就回来了""某某价位的多有没有救""扛单等回本""我不想止损""怕损了再回来"。
- **鸵鸟 / 掩耳盗铃**（ep-2026.8.26 L01057–L01069）。陷阱：遇到问题不面对，靠"信念感"支撑，不验证方式可行性。机制：不敢面对自己、不敢用数据检验方式，靠"我感觉能下去"支撑；应该打回测拿数据、拆解亏损订单归因。预警信号："我感觉我那个方式能盈利""用信念而非数据判断"。
- **扛单、不设止损**（ep-2026.7.25 L1772、L1080）。陷阱：做订单不带止损、被套后不割肉死扛，逻辑是"我不卖我就不亏"。机制：止损单笔看是敌人、整体看是朋友；侥幸扛单从亏损扛到盈利会强化侥幸心理，下一次更信侥幸，直到一次加速行情被拉爆。预警信号："我不割肉就不亏""扛一扛就回来了"。
- **看账户资金变化做交易**（ep-2026.8.5 L12、L20）。陷阱：凭账户资金涨跌做决策——亏损时死扛硬扛、反而"能拿出单了"，盈利时马上平仓卖飞；问"我被套了如何解套"，而行情涨跌与自己盈亏毫无关系。原文："第一个维度呢 就是你通过账户的资金变化去做交易……那这种情况你亏损的时候呢 你就开始死扛硬扛 反而能拿出单了"。机制：纯资金驱动是意淫，是亏损根源。预警信号："亏了我就死扛，反正不卖不亏""赚一点就想跑"。
- **被套死扛、要求解套**（ep-2026.8.22 L61、L65）。陷阱：被套还一直拿着、还问怎么解套，或开对冲单。原文："不要有被套的订单 我很不希望听到你们说将给我解套了……你逻辑都被否认了 我就整不明白为什么要一直拿呢"。机制：做多是想它涨，没涨就代表逻辑错了，就该走。预警信号："能不能给我解套""被套了开个对冲单"。

### 作者的盲点 / 时代局限

- **"从不被套"是理想态，不是可达状态**。作者的结论建立在"进场必带止损且止损挂在逻辑否认点"这一前提上；对已经深度被套的存量单，本能力只给了"逻辑被否认就了结"，没有给分批减仓等过渡处理。
- **"逻辑被否认"未量化**。收盘确认还是影线触及，原文未给；本卡用收盘穿越作为实现约定。
- **被套判定不设门槛可能与"浮盈回吐"混淆**，需要使用者先有明确的逻辑否认点，否则两个状态无法区分。
- **"跳出资金驱动"缺量化方法**。新材料把"看账户资金变化做交易"列为失败模式，但"如何量化自己是否跳出了资金驱动"原文未给，只能靠行为层判据（是否凭盈亏而非逻辑决策）。
- **标的与平台语境**。内容围绕黄金 CFD 与加密合约，作者自承数据行情滑点极大，"按价了结"的假设会失效；这类平台在中国大陆不受法律保护，作者本人也承认"不敢说自己是做这个的"。全篇不构成投资建议。

### 容易混淆的邻近方法论

- **"等回本"**：那不是处置，是把决策权交给价格；本能力要求由逻辑是否被否认来决定。
- **"分批止损"**：本能力不讨论分批，只给二值判定；分批属于仓位层面的动作，原文未展开。
