# 健康订单与不做包容行为

## R — 原文（Reading）

> 这是一个健康订单／就是你做哪怕说你就给这订单扔一块钱／也需要要求什么／也需要要求这个订单是一个正常的订单／是你挑不出来问题的订单／哪怕你就给他一块钱／也是要这种订单／而不要做任何包容的行为

— 交易员江河，ep-2026.9.14 L01600

---

> 学东西的目的不是为了增加交易机会／而是让你变得挑食

— 交易员江河，ep-2026.8.14 L01723

---

## I — 方法论骨架（Interpretation）

这套方法给"起步点"设了一道很高的门槛：一笔订单，无论最终给多少仓位——哪怕只给一块钱——它本身必须是一个"挑不出问题的正常订单"。作者把"因为条件不完美而用小仓位将就"这种行为叫"包容行为"，并明确禁止：有劣质条件时应该直接不做，而不是降仓去做。所以仓位不是劣质条件的稀释剂，而是健康订单之间的分配手段。

这里的"健康"不是"能赚钱"，而是"挑不出逻辑毛病"。它的判据来自必要条件清单：方向、节奏、位置、信号四要素齐备，且每一项都能被明确说清。只要有一项缺失或带瑕疵（例如信号出现在非关注位置、位置顶着关键位），这笔单就不是健康订单，就落进"包容行为"，结论是零——不做。

一个推论是：学习的目的不是增加交易机会，而是让人变得"挑食"、机会变少。作者说"学得越多，你一定越挑"，审美随之提高，最后只做完全符合审美、非常高质量的单子。这与新手直觉相反——新手往往以为学得越多能做的越多，结果越做越亏。所以"起步门槛高"本身就是学习成果的体现。

再往上一层，健康订单只是"评分系统"的及格线。在及格之上，订单还要按加分／不加分／减分分级：加分订单用正常仓位，不加分（但非减分）的订单用半仓，减分订单根本不做，且只做递减不做递增。本能力负责的正是这道"是否及格"的判定，及格之后的分档交给仓位能力。

## A1 — 应用示例（Application Example）

### 示例 1: 四要素清单逐项检查，发现劣质项 → 不做
- **类型与来源**: 原书未提供该订单案例，以下为合成演练（判据口径来自 `necessary-conditions` 的"包容行为"定义）
- **问题/输入**: 一笔候选做多单。使用者已填好四要素：方向＝多头、节奏＝第二次推动、位置＝某个关键位、信号＝一根阳线。但补充说明里写着"价格是直接顶着上方一小时前高做的"。
- **方法论的使用**:
 1. 先跑必要条件清单，四要素形式上齐备；
 2. 再逐项标注加分／不加分／减分——"位置"一项是顶着关键位，属劣质条件（对应 ），标为**减分**；
 3. 按健康订单定义，"哪怕给一块钱也要挑不出问题"；此单有减分项 → 不是健康订单 → 属包容行为；
 4. 结论只能是"不做"，不能改成"半仓做"。
- **结论**: 判为不健康，不做。
- **结果**: 合成演练，无真实成交结果（未说明）。

### 示例 2: 19 岁学员问"小资金该重仓还是轻仓"
- **类型与来源**: 原书转述的连麦案例（ep-2026.9.3 L01713、L01738、L01826、L01836）
- **问题/输入**: 18 岁入行、现 19 岁的学员自述一年多亏八九万、爆仓、休学在家；问小资金做大该重仓还是轻仓。
- **方法论的使用**: 作者不接受"重仓／轻仓"这个二选一，而是先回到起步点——小资金也必须做健康订单，用筹码分配区分轻重："没加分项 50 美金、有加分项 150 美金"（原文口径），而不是靠重仓赌一把或一律轻仓。
- **结论**: 起步点仍是"健康订单＋评分"，先积累经验、别急着赚钱。
- **结果**: 原书交代：学员此前已爆仓（剩少量资金），作者判定其当前不具备赚钱能力。

## A2 — 触发场景（Future Trigger）★

### 用户会在什么情境下需要这个能力？

1. 用户说"这单感觉一般，那就小仓位做吧"——典型的包容行为。
2. 用户已经给订单分了档，问"什么样的单子才配用正常仓位"。
3. 用户学了很多技术，发现交易机会变多了、反而亏得更多了。
4. 用户问"起步阶段应该做什么样的单"。
5. 用户在某笔单里发现一个条件不满足（如顶着关键位），问"能不能降仓做"。

### 语言信号（用户的话里出现这些就应激活）

- "小仓位试试 / 先拿半仓将就一下"
- "这单条件差一点，但我想做"
- "健康订单 / healthy order"
- "越学机会越多"（反例信号）
- "挑食 / 提高审美 / 起步门槛"

### 与相邻能力的区分

- 与 `setup-gate` 的区别: setup-gate 判"要不要进入评估"（认知／犹豫），是更靠前的资格闸门；healthy-order 在"已决定要做"之后判"这笔单的质量够不够格当起步点"。
- 与 `necessary-conditions` 的区别: **本能力的判据直接由 necessary-conditions 的必要条件清单推出**——四要素齐备且无劣质项 = 健康订单；任一要素缺失或有瑕疵 = 包容行为，直接不做。两者是"清单"与"用清单判及格"的关系，E 段有明确依赖步骤。
- 与 `position-allocation` 的区别: healthy-order 输出的是 0 或 1（够不够格当起步点）；position-allocation 决定健康订单之间给几成仓（评分／只递减不递增）。先过本关，才进分档。
- 与 `no-binary-thinking` 的区别: no-binary-thinking 说"不能做多≠能做空"，主张因子可调；healthy-order 说"有劣质条件→不做"。边界在于：方向这类因子可以换（可调），但订单质量不达标时**不允许**用"小仓位"来中和。

## E — 可执行步骤（Execution）

**必需输入**: 候选订单描述；`necessary-conditions` 的四要素齐备性结果（方向／节奏／位置／信号各一行）；使用者的加分／减分项清单（字段：条件名、标签∈{加分, 不加分, 减分}）。

**交付物与完成标准**: 输出 `健康` 或 `不健康` 的二值判定；若为"不健康"，必须列出全部劣质条件。完成标准：`不健康` 时输出中**不得**出现任何仓位建议（不能给半仓）；只有 `健康` 或"无减分项但有加分项缺失"的订单才被允许转交 `position-allocation` 分档。

**与 necessary-conditions 的依赖关系（关键）**: 本能力不自己发明判据，而是**消费** necessary-conditions 的输出。执行顺序固定为：先跑 necessary-conditions 得到"齐备／缺项清单"，再把每一项按"加分／不加分／减分"贴标签。缺项 = 劣质条件 = 包容行为 = 不做。没有这一步，健康与否无从判断。

**实现约定**: 加分／减分项的具体清单与评分规则原文未给（原文：作者称筹码分配完整公式需看其大号视频）；各档仓位的具体数值、"瓶颈"的量化阈值也未给。本卡要求使用者自建这份清单，属**实现约定**，不改变"起步点必须是挑不出问题的订单"这一原意。

当能力被激活后，agent 应按以下步骤执行：

1. **跑必要条件清单**
 - 完成标准: 拿到四要素的"齐备／缺项"结果（若尚未跑，先调用 `necessary-conditions` 的 E 段）。
2. **逐项贴标签**
 - 完成标准: 每一项条件都被标为"加分／不加分／减分"三者之一，无空白项。
3. **检查减分项**
 - 完成标准: 明确回答"有没有减分项"。
 - 判停条件: 存在任一减分项 → 判 `不健康`，**终止**，输出劣质条件清单，不进入任何仓位计算。
4. **检查加分项缺失**
 - 完成标准: 无减分项时，判断是否存在"不加分"项。
 - 分支: 有"不加分"项 → 订单尚不构成健康起步点，标记为"半仓候选"（交 `position-allocation`）；全部加分 → 标记为健康订单／天选单。
5. **二值化输出**
 - 完成标准: 输出 `健康`（含"半仓候选／正常仓候选"标记）或 `不健康`；`不健康` 时只给劣质条件，不给仓位。

## B — 边界（Boundary）★

### 不要在以下情况使用

- **用"小仓位"绕过本能力**。降仓不是豁免，作者明确禁止；有劣质条件时的唯一正确结论是不做。
- **把"健康"等同于"会赢"**。健康只是"挑不出逻辑毛病、可复制"，不改变概率。
- **替代 `position-allocation`**。本能力只回答"能不能当起步点"，不回答"给几成"。
- **在认知之外硬评质量**。看不懂的行情先过 `setup-gate`；对看不懂的行情评"健康"没有意义。

### 作者警告的失败模式

- **硬做（明知高风险仍"小仓位试试"）**（ep-2026.8.14 L01752–L01756、ep-2026.9.14 L00313、ep-2026.9.25 L00903）。陷阱：明知是高风险单还"小仓位试试"，把小仓位当成中和劣质条件的工具。机制：既然知道是高风险单就不该做，该学会弃牌、挑食，而不是明知是"屎"还拿起来吃；小仓位只是把错误缩小，不把错误变对。预警信号："我知道这是高风险单的我小仓位试试吧""做之前就犹豫""明知高风险仍重仓"。
- **做试错订单 / 包容劣质机会**（ep-2026.8.19 L64、ep-2026.9.17 L183）。陷阱：一听到筹码管理就想"质量较差的机会用小仓位试一下"。原文："或者说感觉质量较差的机会订单我少给一点筹码仓位去试一下呢？绝对不会有的"。机制：不允许任何试错/包容订单——发现劣质条件就应直接不做，而非用小仓位将就；起步点必须是挑不出问题的健康订单。预警信号："质量差的我少给点仓位试试""用小仓位试探一下"。
- **两极化思维**（ep-2026.9.3 L01837）。陷阱：仓位只有两个极端——一律单笔 2%，或百分百梭哈。机制：现实中有中间地带，应"该轻的时候轻、该重的时候重"，用评分／筹码分配做相对轻重；本能力要求的正是这个"中间地带的起点"存在的前提。预警信号："网上都说单笔 2% 就单笔 2%""要么就百分百梭哈"。
- **假赢（靠重仓／扛单／不带止损把曲线拉上来）**（ep-2026.9.9 L02822、L01460、ep-2026.9.24 L01061–L01067）。陷阱：用扛单和重仓把资金曲线拉上来，一旦改回仓位管理就赚不到钱。机制：回撤原因与盈利原因同源，本质是假赢不是真赢；说明起步点从来不是健康订单。预警信号："不敢砍重仓／扛单""一周十几倍""一改风控效率砍半"。
- **单点思维**（ep-2026.8.3 L01194）。陷阱：拿一个加分项当必要条件，把不健康的单误判为健康订单。机制：加分项≠必要条件，个别条件单独成立不代表订单挑不出问题。预警信号："到关键位了那我得做"。

### 作者的盲点 / 时代局限

- **加分／减分项清单与评分规则原文未给**。原文 明确写着"加分/减分项的具体清单与评分规则原文未给出"，各档仓位数值与"瓶颈"量化阈值也未给出，作者称筹码分配完整公式需看其大号视频。因此"健康"的边界仍由使用者自定。
- **健康与否是主观审美，无法外部验证**。"挑不出问题"依赖使用者自己的判据；同一个人在不同状态下对同一笔单可能给出不同标签。
- **作者自身的"挑食"标准未被量化**。原文只说"学会狂一点""提升审美"，没有给出可评测的及格线。
- **合规与平台语境**。内容围绕黄金 CFD 与加密合约，这类平台在中国大陆不受法律保护，作者本人也承认"不敢说自己是做这个的"。与平台规则绑定的操作不蒸馏为通用能力，仅作风险提示；本卡不构成投资建议。

### 容易混淆的邻近方法论

- **"轻仓试错"**：试错单在本体系里有位置，但它仍须是健康订单；"轻仓"不能用来给劣质条件开绿灯。
- **"分散下注"**：把仓位摊到多笔不健康订单上，仍是包容行为的总和，不改变每笔的劣质。
- **"提高胜率靠过滤"**：过滤掉不健康订单确实提高胜率，但那是结果不是理由；本能力的理由是"起步点必须是挑不出问题的订单"。
