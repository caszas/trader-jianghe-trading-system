# 拆订单回测法（拆盈利找必要条件；拆亏损砍条件）

## R — 原文（Reading）

> 拿你的逻辑 / 拿你的逻辑对吧 / 跟市场去碰撞一下 / 大量碰撞一下 / 得到一个结论 / 这个结论得到之后 / 你就心里就安了

— 交易员江河，ep-2026.8.14 L01983–L01989

---

> 先干的第一个事 / 先去把盈利的订单全找出来 / 列出来之后 / 你去看他们的共性 / 你去猜一下它们的共性是什么

— 交易员江河，ep-2026.9.22 L02617–L02621

## I — 方法论骨架（Interpretation）

拆订单回测是把"我觉得这套逻辑行"换成"数据说这套逻辑行"的过程，也是作者口中"把经验外化"的唯一路径。它的目标不是证明系统多厉害，而是把问题暴露出来。

做法被固定成一条流水线：先立一个底层逻辑假设（例如"某个位置一定存在被套订单、存在共识"），再圈定一段历史行情与固定笔数，把震荡、趋势、强势、突破等所有模式在这段行情里**全部跑一遍**，不许凭感觉跳过不擅长的模式。跑完之后做两件归集——把所有盈利单放在一起找共性，把所有亏损单放在一起找共性。若盈利单里高频出现"顺势"，顺势就是必要条件；若亏损单里高频出现"逆势"，逆势就是可以直接砍掉的劣势条件。先把最劣势的模式砍掉，再从剩下的里挑出整体能微盈利的那一个作为主模式，然后在同一段行情上反复迭代。

拿到负向数据后的处理也写死了：把亏损单拆出来分类总结，找出占比最高的共同原因当作改动因子，改完再回测。这条流水线还有第二个用途——治"拿不住单"：跑足量样本（作者举过 1000 单），数据为正就用它建立信心，数据为负就说明方式本身是错的，直接放弃。

有三条态度约束贯穿全程：不看单次看整体；用数据说话，因为"很多人的感觉是错的"；必须本人自己拆、自己统计、自己得结论，不能用信念感替代。

补充（回测的目的与门槛）：回测的目的"只是发现问题、解决问题"，不是看胜率漂亮。原文："让你回撤的目的只是发现问题 解决问题对吧 历史回测的行情 这个时间跨度我认为要长 你回测的订单数量一定要多 最起码也要经历了一轮牛熊"（ep-2025-12-26 L240–L342）。由此补三条要求：① 行情时间跨度要长、至少经历一轮牛熊；② 订单数量要多（原文举 1000 笔为例，未给下限，**原文未给**）；③ 对亏损单按原因统计分类、按权重优先解决主要问题，再总结盈利单找可优化/可复制条件，反复回测；数据达标才上实盘——**胜率 >60%、盈亏比 >1:1**（ep-2025-12-26 L240）。

补充（亏损归因的具体口径）：把过往亏损订单全部列出，逐条标注亏损原因并归类，找出占比最大的那个原因（主要矛盾）先解决；解决主要矛盾后大概率能做到不亏损。若回测 1 万笔仍是稳定亏损，说明系统本身有问题，不要继续执行错误系统，而应去发现问题、解决问题。原文："你一共亏了2000单对吧 然后有800单都是因为一个原因 那你把这个原因解决的就好了"（ep-2026-06-09 L91、ep-2026-07-25 L1261–L1273）。

补充（赚钱之后如何赚更多，放大方向）：① 在原有基础上优化胜率与盈亏比（整理交易记录、分类盈亏单、找关键条件）；② 增加新手法/品种/周期以提高频率（需磨合，防拖累原系统）；③ 用评分系统做筹码分配，在对的机会加大仓位（ep-2026-01-09 L33–L75）。此三者与 `advantage-amplification` 相接。

## A1 — 应用示例（Application Example）

### 示例 1: 学员 4633 拿不住单 → 用回测建立信心
- **类型与来源**: 原书转述案例，ep-2026.8.26 L00982–L01013
- **问题/输入**: 连麦学员自述：下午在 4633 做空（左侧攻防转换位），用 AB=CD 把目标位测算到 4614；价格回调到 4628 时看到疑似双底，就不敢持有、提前离场，实际没到目标位。
- **方法论的使用**: 作者先判定"进场点与目标测算都合理"，即这笔单的逻辑本身没问题；再把问题定性为"不信自己能赚到钱"，而不是进场错误。给出的解法是：用这套方式回测 1000 单，拿数据建立信心；同时把亏损订单拆出来找因子。
- **结论**: 该单不属于逻辑错误，属于执行环节的"不相信"；应通过足量回测数据而非临场感觉来支撑持仓。
- **结果**: 未说明（原文只说提前离场，未交代最终盈亏）

### 示例 2: 固定 100 笔、全模式跑一遍 → 找必要条件
- **类型与来源**: 原书未提供带完整数值的拆单案例，以下为合成演练（ep-2026.8.14 L01983–L01989、ep-2026.9.22 L02617–L02621）
- **问题/输入**: 假设某交易者想验证"关键位附近顺势接回调"这个假设。取同一段历史行情，固定 100 笔机会，把震荡/趋势/强势/突破四种模式全跑一遍，记录每笔的模式、方向、结果。
- **方法论的使用**: ①盈利单归集——统计盈利单中"顺势"的出现频次；②亏损单归集——统计亏损单中"逆势"的出现频次；③把"逆势"标记为劣势条件直接砍掉；④在最劣势模式（如"逆势做突破"）被砍后，从剩余模式里选出整体微盈利的那个作为主模式；⑤在同一段行情上重跑，验证改动是否改善。
- **结论**: 得到一份"顺势＝必要条件、逆势＝劣势条件"的条件清单与一个主模式。
- **结果**: 演练演算，无真实回测结果（未说明）。**注**：最小样本量、占比阈值、样本外验证方法原文均未给出，此处 100 笔与"高频"仅为示意。

## A2 — 触发场景（Future Trigger）★

### 用户会在什么情境下需要这个能力？

1. 用户手上有一套主观总结的"经验"，想知道它到底成不成立，问"我这套逻辑能不能赚钱""怎么验证"。
2. 用户已经亏了一段时间，想找"我到底在什么行情里亏"，需要一套从历史订单里挖条件的流程。
3. 用户持仓时总是拿不住、提前离场，想知道怎么用数据说服自己（对应"拿不住单"）。
4. 用户想砍掉一部分做法，问"我怎么知道哪个模式该放弃、哪个该保留"。
5. 用户面对一堆历史成交记录，不知道怎么从里面读出规律，只会逐笔复盘。
6. 用户问"回测到什么程度可以上实盘"，或长期回测仍稳定亏损、问"要不要继续执行这套系统"。

### 语言信号（用户的话里出现这些就应激活）

- "我想做回测 / 打回测 / backtest"
- "回测达标 / 胜率盈亏比多少能上实盘 / 回测一直亏要不要继续"
- "拆订单 / order deconstruction / 拆单子"
- "从历史订单里找规律 / 找共性 / 找必要条件"
- "我这套逻辑到底行不行 / 拿数据说话"
- "我拿不住单 / 怎么用数据建立信心"

### 与相邻能力的区分

- 与 `review-scope` 的区别: 本能力是**主动构造样本**、把历史同类机会全找出来做统计归集，产出条件清单与主模式；review-scope 管的是"统计时什么算盈亏"的**记账口径**（卖飞不算盈利、概率损不算错）。口径先立，拆单结果才可信；本能力负责"拆"，review-scope 负责"算不算数"。
- 与 `advantage-amplification` 的区别: 本能力负责拆的过程与产物（必要条件、劣势条件、主模式）；advantage-amplification 负责"拆完之后往哪个方向放大"（放大胜率还是放大盈亏比、数据极端化）。本能力回答"我的优势点是什么"，它回答"这个优势点怎么无限放大"。
- 与 `trade-system-build` 的区别: 本能力是 trade-system-build 第三个环节（回测优化）的具体执行方法；trade-system-build 管整体三环节与系统文档结构，本能力只管"怎么拆出条件"。
- 与 `demo-to-live-discount` 的区别: 本能力跑在历史行情或模拟数据上，产出的是条件与信心；demo-to-live-discount 管"模拟盘的结果搬到实盘要打多少折"。

## E — 可执行步骤（Execution）

**必需输入**:
- 一个**底层逻辑假设**（一句话，如"关键位附近会有被套订单形成反弹"）；缺失时先问用户"你想验证的那句判断是什么"。
- **历史行情段**（品种 + 起止时间）与**固定笔数 N**（整数）。
- **模式清单**（如震荡/趋势/强势/突破；至少两类）。
- 每笔记录：所属模式、方向、进场价、止损、离场、结果、是否按系统做。
- **结果口径**：单笔算盈利还是亏损，按 `review-scope` 判定（卖飞/错过不计入）。

**交付物与完成标准**: 输出六件东西——盈利单共性表、亏损单共性表、高频**必要条件**清单、高频**劣势条件**清单、被砍掉的**最劣势模式**、确定的**主模式**（须为"整体微盈利"）。完成标准：每个条件都能追溯到具体笔数与占比，主模式的整体结果为非负。

**实现约定**: 原文**未给出**最小样本量、统计口径（"共性"如何计）、"占比多少算主因"的阈值、样本外验证方法（见原文 原文）。本卡在步骤中给出的"≥100 笔""高频"等仅为**实现约定**，不改变"固定行情段与笔数 → 全模式跑一遍 → 盈亏分别归集找共性 → 砍劣势定主模式"这一原意。使用者须自行写明所采用的样本量与阈值。

当能力被激活后，agent 应按以下步骤执行：

1. **提出底层逻辑假设**
 - 完成标准: 能用一句话写出待验证的判断，且这句话可以被历史数据证实或证伪。
2. **固定行情段与笔数**
 - 完成标准: 明确写出品种、起止时间与固定笔数 N（N 为实现约定，建议 ≥100 并注明来源）。
 - 判停条件: 若用户拿不出任何历史记录，也无法取到历史行情段 → 终止流程，改为先积累记录。
3. **所有模式全上一遍**
 - 完成标准: 每种模式都有记录，且没有"凭感觉跳过"的模式；对跳过的模式要写明理由。
4. **把盈利单与亏损单分别归集找共性**
 - 完成标准: 两张表都列出候选共性，并给出每个共性的出现笔数与占比。
5. **归纳高频必要条件 / 劣势条件**
 - 完成标准: 产出"必要条件"与"劣势条件"两张清单，每条都带占比数据。
6. **砍掉最劣势模式、定主模式**
 - 完成标准: 明确指出被砍掉的一个最劣势模式，以及剩余模式中整体微盈利的主模式。
 - 判停条件: 若所有模式整体均为负 → 回到步骤 1 重新提假设（或按 `advantage-amplification` 换方向），不要硬凑一个主模式。
7. **样本外验证**
 - 完成标准: 换一段**未参与优化**的行情段重跑同一套条件，结论一致；方法本身为实现约定，须在文档里写明所用方式。
 - 判停条件: 若样本外结果与样本内明显背离 → 判定过拟合，回到步骤 5 重新筛条件。
8. **自己得结论并落成文档**
 - 完成标准: 由使用者本人写出条件清单、主模式与后续改动因子，不以他人结论或信念感替代。
9. **亏损归因迭代与达标判定**
 - 完成标准: 若回测结果为稳定亏损 → 列出全部亏损单、逐条标注原因、统计各原因占比，找出占比最高的原因（主要矛盾）优先解决后重跑；行情跨度须至少经历一轮牛熊；数据达标（**胜率 >60%、盈亏比 >1:1**，为达标门槛，出自 ep-2025-12-26 L240）才上实盘。
 - 判停条件: 未达标 → 不得上实盘；占比阈值与订单数下限原文未给（**原文未给**）。

## B — 边界（Boundary）★

### 不要在以下情况使用

- **没有一个可证伪的底层逻辑假设时**。这时回测会退化成"随便跑数据"，跑得再多也得不出条件；本能力的起点是假设，不是数据量。
- **样本量明显不足、或只有最近几笔时**。此时"共性"是噪声不是规律，任何占比都不可信（最小样本量原文未给，须使用者自定并披露）。
- **把它当成"证明系统牛逼"的工具**。本能力的目的是发现问题；带着"证明我对"的动机做回测，会不自觉地只归集有利数据。
- **用回测替代实盘执行**。回测只能建立信心与条件，不覆盖滑点、跳空与真实情绪；把它当"我已经练成了"会跳过执行环节。

### 作者警告的失败模式

- **拿不住单（不信自己能赚到钱）**（ep-2026.9.3 L00518、ep-2026.8.26 L01035）。陷阱：持仓中一有风吹草动（疑似双底、回调）就提前离场，拿不到目标位。机制：根因是内心不相信这套方式能赚钱，所以行情稍一反复就走；解法是用回测数据建立信心。预警信号："回调时看到双底就不敢持有""拿不住害怕行情反转""我咋没拿住呢"。**本能力正是它的正解——没有足量回测，信心无从建立。**
- **鸵鸟 / 掩耳盗铃**（ep-2026.8.26 L01057、L01069）。陷阱：遇到问题不面对，靠"信念感"支撑，不验证方式可行性。机制：不敢用数据检验方式，用"我感觉能下去"替代统计；应该打回测拿数据、拆解亏损订单归因。预警信号："我感觉我那个方式能盈利""用信念而非数据判断"。**这直接使本能力无法启动。**
- **把回测当刷题海战术**（ep-2026.10.5 L00308、L00312）。陷阱：做回测只追求做了多少笔，不做复盘。机制：没有复盘过程，回测就失去意义——重点是复盘过程，不是笔数。预警信号："把回测当刷题海""只看做了多少笔"。**本能力的产出是条件，不是笔数。**

### 作者的盲点 / 时代局限

- **四项关键参数原文全部缺失**。原文明确记录：拆解所需的最小样本量、"共性"的统计口径、分类维度与"占比多少算主因"的阈值、样本外验证方法，原文均未给出。这意味着本能力在方法上是**不完整**的——没有样本外验证，样本内的"必要条件"极可能是过拟合。（**部分修正**：新材料补入"至少经历一轮牛熊""订单数量要多（举例 1000 笔）""胜率 >60%、盈亏比 >1:1 才上实盘"（ep-2025-12-26 L240–L342），但最小样本量下限、占比阈值与样本外验证方法原文仍未给出。）
- **"拆亏损单"与"概率损不必复盘"之间存在张力**。作者一面说把亏损单拆出来找共性，一面（见 `review-scope`）说概率损是必要成本、不必刻意复盘。两者的边界（哪些亏损值得拆、哪些是概率损）原文未界定，实操中容易被误用。
- **缺少可复用的记录模板字段**。作者提到"战略复盘/战术复盘"模板，但未给出具体字段，使用者只能自行设计。
- **标的与平台语境**。内容围绕黄金 CFD 与加密合约；作者自承数据行情"杠杆会调、滑点非常大"，历史回测中"按价成交"的假设在极端行情下失效，回测结果会系统性偏乐观。

### 容易混淆的邻近方法论

- **程序化/参数寻优回测**：用代码穷举参数、追求最优参数曲线。本能力是手工拆订单、找必要条件，作者明确反对把它做成"刷题海"。
- **单纯写复盘日记**：那是记录与梳理过程（见文字输出/复盘梳理法），不产出条件清单；本能力要求归集、统计并给出可操作条件。
- **`demo-to-live-discount` 的模拟盘验证**：那是把模拟盘结果折损到实盘；本能力是在历史/模拟数据上找条件，两者前后衔接但产出不同。
