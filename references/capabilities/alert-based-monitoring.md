## I — 方法论骨架（Interpretation）

这套方法解决的是"要不要一直盯着盘面"。作者的回答是不必：先标定一个需要你注意的价格区域，在那个位置挂上条件警报，然后把注意力从屏幕前释放出来去做别的事；价格真正到达警报区，再全职回到盘前观察。

它的前提是"空窗期里没有可执行动作"。当行情以一个较大的推动离开某区域、且该区域的横向结构也大时，可以判断一时半会儿回不来——这段时间人在屏幕前也没有该做的事，盯盘只是在消耗注意力、诱发手痒。

这是一套**注意力/时间分配**程序，不是入场信号。警报只回答"什么时候把注意力切回盘面"，不回答方向、进场、止损：能不能做仍交给 setup-gate，主次周期关系仍交给 timeframe-contract，关注区域由 key-level-reading 提供。

与 `state-and-event-guard` 的分工：后者是数据/事件冷却与精力闸门（数据前留 5 分钟留白、状态差就不做），靠"事件冷却"减少无效动作；本卡靠"条件警报移交注意力"，处理系统暂无可执行动作的空窗期。两者都减少盯盘，但机制不同。

与 `self-check-overtrading` 是**预防**关系：后者处理"不做难受、刺挠"的事后自检；本卡是无动作时间的基础设施，用警报把这段时间结构化地安排掉，从源头减少盯盘触发的参与欲。

原文只给动作口径（设警报、该干啥干啥、到点再看），**未给**"推动/横向结构多大算大"的判据，**未给**警报距离与到达时间的估算方法。这些在实现里必须标"原文未给／实现约定"，不得脑补数值。

## A1 — 应用示例（Application Example）

### 示例 1: 合成演练——关注区域设警报后的看盘时间管理
- **类型与来源**: 原书未提供逐步案例；以下为**合成演练**，流程骨架取自 ep-2026.10.9P2 L922。
- **问题/输入**: 价格以一根大推动离开某关注区域，该区域横向结构也大；用户问这段空窗期要不要一直守在屏幕前。
- **方法论的使用**:
 1. 用 key-level-reading 标出关注区域的价格区间（区域，不是线）。
 2. 看最近推动的空间与横向结构大小，判"一时半会儿回不来"。【原文未给：多大的推动/横向结构算"大"，以及到达时间的估算方法】
 3. 在关注区域边界设条件警报（价格触及即提醒）。
 4. 警报响之前离开盘面，处理其他事务，不主动刷盘。
 5. 警报响后全职在线观察，先跑 setup-gate / timeframe-contract 再决定能否做。
- **结论**: 把"该不该一直看盘"改成"警报响之前不看、响之后再判断"。

## A2 — 触发场景（Future Trigger）★

### 用户会在什么情境下需要这个能力？

1. 用户问"要不要一直盯着盘 / 能不能边做别的事边交易"。
2. 用户已标定关注区域，但价格以大推动走远，纠结还要不要守在屏幕前。
3. 用户因长时间盯盘疲惫、频繁手痒下单，问怎么把注意力从盘面抽离。
4. 用户没时间常看盘，想"到点再回来"，希望规划看盘时间。
5. 用户在等价格回到某个关键位/关注区域，但不想一直盯。
6. 用户把本卡误用为"设了警报就不用判断能不能做"，需要澄清边界。

### 语言信号（用户的话里出现这些就应激活）

- "要不要一直盯盘 / 盯盘太累 / 没时间看盘 / 到点再看" / "screen-watching / monitor the market all day"
- "设个警报 / 到价提醒 / 价格到了叫我" / "price alert / notify me when price reaches"
- "价格走远了还等不等 / 一时半会儿回不来" / "wait for price to come back"
- "关注区域 / 关键位到了再看" / "attention zone / key level reached"
- "盯盘就手痒 / 总想点开看" / "can't stop watching charts"

### 与相邻能力的区分

- 与 `state-and-event-guard` 的区别: 后者是数据/事件冷却与精力闸门（数据前留白 5 分钟、状态差就不做）；本卡管"用条件警报把注意力从盘面释放出来"，处理系统暂无可执行动作的空窗期。
- 与 `self-check-overtrading` 的关系: 后者是过手瘾的事后自检；本卡是其**预防**手段——用警报结构化占用无动作时间，减少盯盘触发的参与欲，二者是预防与自检的配合关系，不是同一件事。
- 与 `setup-gate` 的区别: setup-gate 判定"这一单能不能做"；本卡只决定"何时把注意力切回盘面"，不产出做/不做结论。
- 与 `key-level-reading` 的区别: key-level-reading 负责把关注区域画出来；本卡消费这个区域来设警报，不负责画区域。
- 与 `timeframe-contract` 的区别: 周期契约约定主/次周期的分工；本卡不分配周期，只分配注意力时间点。

## E — 可执行步骤（Execution）

**必需输入**: 已标定的关注区域（价格区间，来自 key-level-reading）；当前价格与最近一段推动的空间大小、该区域的横向结构大小；用户此期间是否有其他事务可安排。缺失时问："你的关注区域是哪一个价格区间？""价格是不是以一根大推动离开了它？""这段时间有没有别的事要处理？"

**交付物与完成标准**: ① 警报设置记录（关注区域边界、触发方式、触发后动作）；② 一段可自由支配的离屏时间；③ 触发后的判断清单（回到 setup-gate）。完成标准：警报挂在关注区域边界且写明"到达即提醒"；离屏时间有具体安排；触发后指向既有闸门而非直接下单。

**缺口标注（实现约定）**: 原文只给动作口径（"在这位设个警报""该干啥干啥""到点再看"），**原文未给**"推动空间多大/横向结构多大算大"的判据，**原文未给**警报距离与到达时间的估算方法或误差范围。步骤 2 中若要把它转成数值，只能作为**实现约定**填写并注明非作者口径，不得脑补数值。

1. **标定关注区域**
 - 用 key-level-reading 画出价格区间（区域，非线）。
 - 完成标准: 给出可指名的区间上下沿。
2. **判断"一时半会儿回不来"**
 - 看最近推动的空间大小与该区域的横向结构大小；两者都明显大时才判"回不来"。
 - 完成标准: 给出"回不来/可能会回"的定性结论。
 - 缺口: 【原文未给】推动与横向结构"大"的阈值、到达时间的估算方法与误差范围；需要数值时用**实现约定**填写。
 - 判停条件: 若判"可能很快回来" → 不使用本卡，维持正常盯盘或改判不做。
3. **在关注区域设条件警报**
 - 完成标准: 警报条件 = 价格触及关注区域边界，触发方式写明（到价提醒）。
4. **安排离屏时间**
 - 完成标准: 明确警报响之前要做的具体事务，并承诺不主动刷盘。
 - 判停条件: 若用户仍忍不住频繁看盘 → 移交 self-check-overtrading 处理手痒，不在本卡内解决。
5. **警报触发后回到盘面**
 - 完成标准: 全职在线观察，先跑 setup-gate / timeframe-contract 判定能否做；本卡不直接产出进场结论。
 - 判停条件: 若判"不能做" → 重新设警报、继续离屏。

## B — 边界（Boundary）★

### 不要在以下情况使用

- **关注区域尚未标定、系统没有明确关注对象时**。没有区域就没有可挂警报的位置；先走 key-level-reading 与 setup-gate。
- **价格可能很快回到区域时**。原文前提是"大推动 + 大横向结构 → 一时半会儿回不来"；不满足时离屏会错过触发。
- **用警报替代进场/离场判断时**。警报只管注意力切换，不管能不能做、仓位与止损；这些仍归 setup-gate、timeframe-contract 与离场类能力。
- **已持仓且需持续盯止损时**。本卡处理"等待关注区域"的空窗，不是"持仓中需盯盘"的场景；持仓专注另见 state-and-event-guard 的相关段落。

### 作者警告的失败模式

- **盯盘诱发手痒、为参与而参与**（ep-2026.9.14 L01664）。陷阱：没动作时也守在屏幕前，被 K 线勾引下单；机制：盯盘把"等待"变成"刺激"，参与欲由刺激驱动；预警信号："不做难受 / 刺挠 / 我就得做单"。本卡是预防，与 self-check-overtrading 的事后自检配合。
- **把"能等"当成"硬等"**（ep-2026.10.9P2 L3256–L3273）。陷阱：为了等而等，忽略上方关键位对空间的压缩；机制：作者"能等起、宁可错过也不做错"是有取舍前提的，不是任何机会都死等；预警信号："反正设了警报就一直等"。
- **在噪音区反复改警报**。陷阱：缠绕区信号反复，频繁改警报等于变相盯盘；机制：噪音区内没有可执行的到达事件，警报失去意义；预警信号："警报又响了 / 再调一下位置"。（原文未给"缠绕"的量化判据，需结合信号过滤规则。）

### 作者的盲点 / 时代局限

- **"一时半会儿回不来"无量化标准**。原文未给推动空间、横向结构大小的阈值，也未给到达时间估算方法与误差范围；这是本卡最大缺口，实现中只能标为**原文未给／实现约定**。
- **"该干啥干啥"未定义离屏期间的风控兜底**。离屏期间若跳空或出现极端行情，警报未必能在可成交价位触发；原文未处理。
- **警报依赖交易平台功能**。原文未说明用何种工具、警报在移动端/桌面端的可靠性差异。
- **标的与平台语境**。内容围绕黄金 CFD 与加密合约，这类平台在中国大陆不受法律保护；本卡不构成投资建议。

### 容易混淆的邻近方法论

- **事件/数据日历提醒**: 那是 state-and-event-guard 的数据冷却；本卡提醒的是价格到达关注区域，不是事件公布时间。
- **到价单 / 移动止损**: 那是成交与离场工具；本卡的警报只"叫你回来看"，不自动成交，也不替代止损。
- **按精力排盯盘时段**: 那按个人精力峰值安排；本卡按"价格是否到达关注区域"安排注意力。
