# 离场二选一（卖飞 vs 利润回撤）

## R — 原文（Reading）

> 就是你能接受卖飞还是能接受利润回撤/这个必选题选一个的/我看你能接受哪个/我就给你方案了

> 哎我既不想卖飞 / 我又不想回撤啊 / 那基本上你两样你都得不到

## I — 方法论骨架（Interpretation）

离场不是"优化"出来的，是"选"出来的。交易者面对的是一道**必选题**：能接受卖飞，还是能接受利润回撤。二者不可兼得，必须选一个，没有第三种答案。

选完才谈方案：
- 接受**卖飞** → 给**敏感离场**（等一个减弱信号就走）。代价是趋势继续时你已经在场外。
- 接受**利润回撤** → 给**钝化离场**（等结构被打破或"推左一"才走）。代价是利润会吐掉一大段，甚至被打成亏损。

作者反对"折中/中性化"。折中在理论上或许存在，但执行时一定带来新问题，让人"左右脑互搏"，最终两样都得不到。新手尤其要**数据极端化**：把一个数据追求到极端，方便执行；均衡化是后期守财才用的。

选定之后，关键变成**一致性重复执行**。比如"推保本"这个动作本身没有错，错的是"这次推、下次不推"——那样数据就不一致，回测与复盘都失去意义。选"移动止损"就每笔都移动（不吃回撤，缺点是被打掉后行情继续走）；选"扛回撤"就接受可能被打成亏损。

新材料把"卖飞"的判定口径从"行情涨了多少"拉回到"进场前的预期"："你是不是卖飞呢它不取决于行情涨了多少而取决于你进场前的一个预期是什么……如果你进场前你做的就是剥头皮做的就是短线那你敏感离场就没有问题反而硬要格局那才有问题"（ep-2026.5.18 L29）。据此，判"算不算卖飞"不看离场后价格又走了多远，而看离场行为是否与进场前对该单的规划一致：进场前做剥头皮/短线，敏感离场就正确、硬要格局才错；进场前做趋势单，被微弱回调吓跑才是卖飞。

由此"拿不住单"被归因成两类——① 没有交易系统，靠感觉与情绪下单；② 有系统但不自信、执行不下去，解法是打回测证明系统有效（作者举例 1 万笔盈利 7000 笔）；若回测稳定亏损，则说明系统本身有问题，应改系统而非硬执行（ep-2026.6.9 L17、ep-2026.7.25 L676）。回测样本量与"系统有效"的量化门槛原文未给。

## A1 — 应用示例（Application Example）

### 示例 1: 学员吃到 20 美金却拿不住
- **类型与来源**: 转述案例（ep-2026.9.10 L00722）
- **问题/输入**: 学员说"我昨天两次吃到 20 美金的点位，但是都拿不住，按我的离场规则可能就走了；因为想做波段，所以想格局一下，但这两天的行情好像不是"。
- **方法论的使用**:
 1. 识别出这是必选题：他既想按原离场规则走（接受卖飞），又想"格局一下"拿满（接受回撤）
 2. 指出两种诉求不能同时满足
 3. 逼出选择：要么接受卖飞、按原规则执行；要么接受回撤、改用钝化离场
 4. 选定后要求一致性执行，不再"这次这样、下次那样"
- **结论**: 这是必选题，选了就要受着。
- **结果**: 原文未说明（作者指出这是必选题）。

### 示例 2: 合成演练 —— 把必选题落到两套方案上
- **类型与来源**: 原书未提供对应数值案例，以下为合成演练（口径来源 ep-2026.8.26 L00801、ep-2026.9.22 L01856）
- **问题/输入**: 用户持仓有浮盈，问"有没有一种方式既不卖飞又不回撤"。
- **方法论的使用**:
 1. 直接拒绝折中诉求：中性方式理论上存在，但 99% 执行不了
 2. 给出必选题：A 能接受卖飞吗？B 能接受利润回撤吗？
 3. 用户答"能接受卖飞" → 输出**敏感离场方案**：动能一减弱就走，接受趋势继续时在场外
 4. 用户答"能接受回撤" → 输出**钝化离场方案**：等结构被打破/推左一才走，接受利润回吐
 5. 锁定所选方案，写出"一致性执行清单"：每笔都按同一标准，不允许临场改标准
- **结论**: 只给一套方案，另一套明确舍弃并写进"舍弃项声明"。
- **结果**: 演练，未说明。

## A2 — 触发场景（Future Trigger）★

### 用户会在什么情境下需要这个能力？

1. 用户问"有没有一种离场方式既不卖飞又不回撤"。
2. 用户说"我拿不住单"，想找一个能兼顾的折中方案。
3. 用户刚被卖飞或被回撤打掉，想改离场规则（"我是不是该改改"）。
4. 用户准备定制自己的交易系统，需要确定离场偏向。
5. 用户问"推保本到底对不对"。
6. 用户问"我这笔到底算不算卖飞""我是不是拿不住单"，需要按进场前预期做诊断。

### 语言信号（用户的话里出现这些就应激活）

- "有没有一种方式既不卖飞又不回撤 / 折个中 / 中性"
- "我拿不住单 / 想格局一下 / 又想落袋为安"
- "卖飞 / 利润回撤 / 大回撤 / 被打回原形"
- "推保本到底对不对 / move stop to breakeven 对不对"
- "tradeoff / 必选题 / 我该选哪个"
- "这笔算不算卖飞 / 拿不住单怎么诊断 / 对了也是错"

### 与相邻能力的区分

- 与 `dynamic-exit` 的区别: 本能力是**选择框架**——逼出"敏感还是钝化"的明确选择；dynamic-exit 是**执行机制**——在选定之后具体判断"该不该走"。顺序是先选、后判，不可颠倒。
- 与 `advantage-amplification` 的区别: 本能力处理的是"离场维度的取舍"；advantage-amplification 处理的是"胜率与盈亏比不可兼得、数据极端化"这个更上层的取向。两者共享"不可兼得、必须选一个"的逻辑，但对象不同。
- 与 `stop-loss-mechanics` 的区别: 本能力决定"要不要推保本/移动止损"这个**方向性选择**（选移动就每笔都移动）；stop-loss-mechanics 规定移动止损的**具体机制**（一比一推、按结构点推）。
- 与 `order-exit-discipline` 的区别: order-exit-discipline 规定出口的合法集合；本能力规定在合法出口之内"用哪种风格"。比如"推保本"是否属于合法出口，由 order-exit-discipline 判定；一旦允许，是否每笔都推，由本能力的一致性要求管。

## E — 可执行步骤（Execution）

**必需输入**: 用户的持仓风格与交易频率（用于判断偏向可行性）；用户对"卖飞"和"利润回撤"的接受度（**必须由用户明确回答，不得替他假定**）；用户当前的离场规则（若有）。

**交付物与完成标准**: 输出一份**离场方案书** —— `选定偏向`（敏感 / 钝化）、`离场触发条件`（具体到"看到什么就走"）、`明确舍弃项`（写清"我放弃的是卖飞还是回撤"）、`一致性执行清单`（哪些动作每笔都做/都不做）。完成标准：偏向必须是**二选一**的单一值；方案书中不得同时出现"减弱即走"与"等结构打破"两套触发条件；必须写明舍弃项。

**实现约定**: 原文给出的是"敏感/钝化二选一"这一框架，未给出①偏向的判定依据（什么性格、什么数据该选哪型）；②"减弱""结构打破"的精确标准。本卡把"**先用两个问题逼出选择、再锁定一套**"的流程，以及"**偏离项必须显式写出**"作为实现约定；具体触发口径复用 `dynamic-exit` 的实现约定。

1. **提出必选题**
 - 完成标准: 用户明确回答"能接受卖飞"或"能接受利润回撤"其中之一。
 - 判停条件: 用户回避、要求"折中/中性/两个都要" → **不接受**，说明折中会左右脑互搏，回到步骤 1 重问（最多两轮，两轮后仍回避则告知无法给出方案）。
2. **据选择分派方案**
 - 完成标准: 选卖飞 → 敏感离场方案；选回撤 → 钝化离场方案。只输出一套。
3. **写出离场触发条件**
 - 完成标准: 条件具体到"哪一类 K 线/结构出现就走"，且只含所选偏向的判据（口径见 `dynamic-exit`）。
4. **写出舍弃项声明**
 - 完成标准: 明确写"我放弃的是 X"，并写明放弃 X 的代价。
5. **写出一致性执行清单**
 - 完成标准: 列出"每笔都必须做"与"每笔都不做"的动作（例如：选钝化则"每笔都不推保本"；选敏感则"每笔都在减弱信号出现时走"）。
 - 判停条件: 若用户坚持"这次推保本、下次不推"→ 判定为数据不一致，要求改为一律推或一律不推。
6. **回填到交易系统**
 - 完成标准: 把该方案写入交易系统的离场段（见 `trade-system-build`、`write-loss-action`），供后续一致性检验。
7. **诊断"拿不住单"（新增）**
 - 完成标准: 先对照进场前对该单的规划，判断离场行为是否与之一致——不一致即为"知行不一"（哪怕盈利也是错，见 B 段）；再判断拿不住的归因：① 无系统（靠感觉/情绪）→ 先按 `trade-system-build` 建系统；② 有系统但不自信 → 打回测验证系统有效性（见 `order-deconstruction-backtest`）。
 - 判停条件: 回测稳定亏损 → 说明系统有问题，应改系统，而不是要求用户"硬执行"。
 - 门槛说明: 作者举例"1 万笔盈利 7000 笔"作为系统有效的示意，样本量与"有效"的量化门槛原文未给。

## B — 边界（Boundary）★

### 不要在以下情况使用

- **用户还没有任何离场规则时**。此时先让他按 `dynamic-exit` 建立一套最简规则，再谈偏向；没有基线，"敏感还是钝化"无从比较。
- **把它当成"随便选一个都行"**。偏向必须与用户的执行能力匹配，选完要能一致性重复；选完做不到，等于没选。
- **在单笔订单上临时改偏向**。这正是本能力要防的失败模式。

### 作者警告的失败模式

- **追求数据均衡化 / 中性化 / 兼顾两头**（ep-2026.8.7 L00813–L00827、ep-2026.8.26 L00852–L00903）。陷阱：想用技术手段同时解决卖飞和回撤，离场时既不想卖飞又不想回撤；新手想让频率、盈亏比、胜率都"说得过去"。机制：折中虽可能实现，但一定带来新问题，导致"左右脑互搏"、执行不了；二者不可兼得，一定得选一个。预警信号："我折个中行不行""有没有一种方式既不卖飞又不回撤""什么都想兼顾"。
- **知行不一（剥头皮做波段 / 趋势单被吓跑）**（ep-2026.5.18 L60、ep-2026.6.9 L27）。陷阱：进场前想做剥头皮、结果拿成波段，或进场前想做趋势单、却被微弱回调吓跑。原文："那如果说我做剥头皮订单反而我却拿到了一个波段的利润那才是有问题能懂吗这叫什么知行不一左右脑互搏"。机制：这是操作变形，哪怕结果盈利也是错的（"对了也是错"），因为它会让人以后不再严格执行系统，陷入"这次走不走"的恶性循环。预警信号："我本想做短线结果拿成了波段""本来想做趋势却被一根回调吓出来"。
- **拿了一比一还想拿一比二（贪婪）**（ep-2026.8.3 L330、L211）。陷阱：做一比一短线时贪心想拿一比二。原文："你做短线的话 做一比一的话就不要太贪婪了 不要想着说我拿了一比一 我还能拿个一比二好吧 不要有这种想法……发现动能不足 马上砍"。机制：与所选偏向（接受卖飞、做一比一）冲突，属于临场改标准；发现动能不足要果断砍仓，平仓后再飞也与自己无关。预警信号："拿了一比一还想拿一比二""平仓后价格又飞了我很后悔"。

### 作者的盲点 / 时代局限

- **偏向的判定依据原文未给**。作者只说"我看你能接受哪个"，没给"什么数据/性格适合哪型"的对应关系。
- **"系统有效"缺量化门槛**。新材料以"1 万笔盈利 7000 笔"作为系统有效的示意，但样本量与"有效"的阈值原文未给；"知行不一"的判定依赖进场前对该单的规划记录，若进场时没写下规划，事后无法核对。
- **"一致性执行"缺少验证工具**。作者强调数据要一致，但未给"如何检测自己是否一致"的方法（可用 `review-scope` 的复盘口径部分补足）。
- **把"必选题"推得很绝对**。原文否定一切折中，但作者自己也提到"理论上讲有"中性方式；对老手而言，阶段性切换偏向是否可行，原文未讨论。
- **标的与平台语境**。内容围绕黄金 CFD 与加密合约，作者自承数据行情滑点极大，"卖飞/回撤"的实际幅度会被滑点放大；这类平台在中国大陆不受法律保护，作者本人也承认"不敢说自己是做这个的"。全篇不构成投资建议。

### 容易混淆的邻近方法论

- **"固定盈亏比 + 移动止盈"并用**：两者会打架；作者要求先明确一个偏向，再决定固定还是移动。
- **"看情况灵活处理"**：那不是灵活性，是没有规则；本能力明确要求选定并一致执行。
