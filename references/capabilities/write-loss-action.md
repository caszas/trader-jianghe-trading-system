# 亏损后动作写死（交易系统的最后一段）

## R — 原文（Reading）

> 你交易系统中／你比如说除了前面那个识别盘面行情啊／或者说订单的交易匹配啊／或者什么仓位管理／这交易系统几个环节吗

— 交易员江河，ep-2026.8.14 L00756–L00789

---

> 构建出一个明确离场逻辑／然后定一个偏向出来／是能接受大幅回撤／还是能接受麦菲／选一个

— 交易员江河，ep-2026.9.24 L02600

## I — 方法论骨架（Interpretation）

交易系统的常规环节是"识别市场 + 参与市场"（看盘、匹配订单、管仓位），这些都在描述"没亏的时候做什么"。作者要求补上最后一段，而且是**必须写死的一段**：当我的逻辑被否认、这笔单亏了之后，我要做什么。

"写死"的意思是：不留弹性、不留"看情况"。因为亏损发生的当下正是情绪最强、判断力最差的时候——如果此时才决定"要不要停手""要不要再进一单"，等于把最关键的决策交给最不理智的自己。写死就是把这个决策提前到冷静的时候做完，亏损发生时只是执行。

配套有两条要求：一是这段规则要能被触发（"逻辑被否认就执行 X""连损几单就执行 Y"），而不是"注意调整心态"这类无法执行的句子；二是离场本身也要有明确条件，至少设定一个（看什么走、按什么推），不能靠感觉走。作者把"捏不住单"直接归因于"没有明确离场逻辑、不相信这套方式能赚钱、没有数据反馈"。

## A1 — 应用示例（Application Example）

### 示例 1: 合成演练——给一套已有系统补写"最后一段"
- **类型与来源**: 原书未提供带文字的"最后一段"范本；以下为合成演练，规则骨架取自 ep-2026.8.14 L00756–L00789 与 ep-2026.9.24 L02600。
- **问题/输入**: 用户已有一套日内交易系统（方向／位置／信号），但每次亏损后都临场决定"再做一单找回来"。
- **方法论的使用**:
 1. 列出系统已有的常规环节（识别盘面、订单匹配、仓位管理）。
 2. 在末尾补写一段，只写"亏损之后做什么"，用 if-then 句式。
 3. 写成可触发、可判定的句子，例如："若本单逻辑被否认并打止损 → 当日不再做同一逻辑；若同一逻辑连损两次 → 当日停手。"
 4. 删掉所有不可判定的措辞（"冷静一下""注意心态"）。
- **结论**: 亏损后的动作从"临场决定"变成"触发即执行"。
- **结果**: 未说明（合成演练）。

### 示例 2: 原书亲历——作者"漏单就推止损"的固定习惯
- **类型与来源**: 原书亲历（cB4-10，ep-2026.9.9 L02924）。
- **问题/输入**: 直播中订单一旦"漏出来"（被观众看到），弹幕可能带来情绪干扰。
- **方法论的使用**: 作者没有临场判断"要不要理会弹幕"，而是提前写死一条规则：单子漏出来就推止损。这样把"是否受外界影响"这个变量从当下拿走。
- **结论**: 一条事先写死的规则，替他挡掉了直播场景下的情绪变形。
- **结果**: 形成固定习惯（原文未给单次盈亏结果）。

## A2 — 触发场景（Future Trigger）★

### 用户会在什么情境下需要这个能力？

1. 用户有交易系统，但系统只写了"怎么进场"，没写"亏了之后怎么办"。
2. 用户反复在同一类亏损后做出冲动动作（加仓、反手、立刻重进）。
3. 用户说"我知道该停手，但当时就是停不下来"。
4. 用户离场全靠感觉，出现"拿不住单"或"赚了不知道什么时候走"。
5. 用户正在写交易系统或复盘自己的规则文档。

### 语言信号（用户的话里出现这些就应激活）

- "亏了之后我该做什么"
- "我系统里没写这个 / 我的规则里缺一段"
- "靠感觉离场 / 我拿不住单 / 捏不住单"
- "写死 / 规则化 / 由规则触发 / rule-based exit"
- "我知道该停手但做不到"

### 与相邻能力的区分

- 与 `emotion-three-step` 的区别: emotion-three-step 是亏损**当场**用三栏拆事实／感受／动作；本能力是**事前**把那段动作写进系统。本能力的产出正是三步法里"第三步"的参照标准。
- 与 `trade-system-build` 的区别: trade-system-build 是整条系统的构建流程（知识点 → 主观构建 → 回测优化）；本能力是这条流程的**最后一段**，只管"亏损后动作"。
- 与 `order-exit-discipline` 的区别: order-exit-discipline 规定出口只有"打止损或赚钱离场"；本能力规定的是**离场之后**（亏损已实现）你做什么。
- 与 `consecutive-loss-stop` 的区别: consecutive-loss-stop 是"连损两次就停"这条具体规则；本能力是"把这类规则写进系统末尾"这个动作，连损熔断是它最常见的填充内容。

## E — 可执行步骤（Execution）

**必需输入**: 用户已有的交易系统环节清单；一笔（或一类）反复出现的亏损后冲动行为；系统里是否已有离场条件。缺失时问："你亏了之后通常第一反应做什么？""你系统里现在写了离场条件吗？"

**交付物与完成标准**: 一段写在交易系统末尾的"亏损后动作"规则，满足：① 每条都是 if-then 结构；② 每条都能被客观触发（有明确触发条件）；③ 不含"冷静""调整心态""看情况"等不可判定措辞。完成标准：拿一段真实亏损复盘，能把亏损事实代入规则并得出唯一动作。

**实现约定**: "交易系统末尾写死亏损后动作"出自原文（ep-2026.8.14 L00756–L00789）；if-then 句式、规则条数、以及"至少写一条离场条件"为**实现约定**（原文只说"最少设定一个"）。

1. **列出系统已有环节**
 - 完成标准: 至少列出"识别市场"与"参与市场"两类环节（如看盘、匹配订单、仓位）。
2. **定位缺口**
 - 完成标准: 明确指出系统当前缺少"逻辑被否认／亏损后做什么"这一段（可用一次真实亏损复盘验证：现有系统对该情形无输出）。
3. **写出触发条件**
 - 完成标准: 每条规则的触发条件可被客观判定（"打止损""同一逻辑连损两次""当日回撤达到 X"）。
 - 判停条件: 若写不出可判定的触发条件 → 回到 `consecutive-loss-stop` / `risk-budget-and-circuit-breaker` 先确定阈值，再回来。
4. **写出对应动作**
 - 完成标准: 动作为可执行命令（停手／不再做同一逻辑／换品种），而非状态描述。
5. **补一条离场条件**
 - 完成标准: 至少写出一个明确离场条件（看什么走），且不依赖"感觉"。
6. **回放校验**
 - 完成标准: 用最近一次真实亏损代入，规则给出唯一动作；若规则之间冲突 → 调整到互斥且覆盖完备。

## B — 边界（Boundary）★

### 不要在以下情况使用

- **在系统还没成型时先写"最后一段"**。这段依附于前段逻辑（"逻辑被否认"要先有逻辑），没有前段的系统写出来的只是空规则。
- **把"写死"理解成"不许改"**。写死针对的是**亏损当下的临场决策**；系统本身仍可经回测迭代（这是 `trade-system-build` 的环节）。
- **用这段规则替代风控**。规则是行为约束，不改变单笔风险敞口。

### 作者警告的失败模式

- **靠感觉离场**（ep-2026.9.9 L01547–L01549）。陷阱：用"感觉该走了"代替明确离场条件；机制：感觉不可验证、无法复制，必然摇摆；预警信号："我觉得差不多了就走""靠盘感离场"。**没有离场条件，就没有可写死的动作。**
- **按心情做，不按系统做**（ep-2026.8.7 L00491–L00501）。陷阱：今天开心多做、难过不做；机制：能不能赚钱与心情无关，市场不看你情绪；预警信号："今天状态不好但想试试""心情好就多做两单"。
- **设了止损止盈仍拿不住单**（ep-2026.9.9 L01528）。陷阱：开单时设了止损止盈，中途遇震荡就提前走；机制：本质是没有明确离场条件、不相信这套方式；预警信号："它一震我就拿不住了"。

### 作者的盲点 / 时代局限

- **"写死"到什么颗粒度原文未给**。作者只说不能留弹性、要明确到"停止交易""连损几单后怎么怎么样"，未给规则条数与覆盖清单，需要使用者自定。
- **规则的触发依赖对"逻辑被否认"的判定**，而作者承认这部分高度主观（"大部分因子在你这个人自身身上"）；判定错，规则再明确也执行错。
- **标的与平台语境**。内容围绕黄金 CFD 与加密合约，这类平台在中国大陆不受法律保护；本能力是行为纪律工具，不构成投资建议。

### 容易混淆的邻近方法论

- **止损设置**：止损是"什么时候离场"，本能力是"离场之后做什么"。
- **交易日志**：日志是事后记录，本能力是事前规则。
